## 1. 文档职责

本文档承载 R1-01 的 Build 输出：把 Project Incubator Skill 1.0 从启动或恢复，到下一轮可恢复入口形成的主运行链路写成可消费的 Skill reference。

本文档不是最终 `SKILL.md`，不定义 Codex Skill 的触发元数据，不创建脚本，不创建模板，也不授权 Git 写操作或 Build 自动化。后续任务可以把本文档作为 Skill 入口正文、任务类型判定、硬性门槛矩阵、Builder 交接闭环和脚本辅助检查的输入。

## 2. 主运行链路总览

Skill 1.0 的主运行链路按以下顺序执行：

```text
启动或恢复
→ 读取本地协议与状态入口
→ 定位 Phase、角色、主目标和权威文档集合
→ 上下文完整性检查
→ 建立本轮协作契约
→ 判断任务类型
→ Phase 内协作或 Builder 执行
→ 新事项分类
→ 触发硬性门槛
→ 文档写回
→ Maker 审阅
→ 状态入口收敛
→ 下一轮恢复
```

链路中的每一步都必须能回答四个问题：

- 输入是什么；
- 输出是什么；
- 什么条件下可以继续；
- 什么条件下必须停止并请求 Maker 决定。

## 3. 运行步骤

### 3.1 启动或恢复

**输入**

- Maker 本轮指令；
- 当前工作目录；
- 项目根目录候选；
- 项目根目录中的 `AGENTS.md`。

**输出**

- 已确认的项目根目录；
- 本轮是恢复现有项目、新项目初始化、只读咨询、任务执行还是 Git 闭环回写的初步判断；
- 需要继续读取的本地协议和状态入口。

**继续条件**

- 找到项目根目录；
- 能读取项目根目录的 `AGENTS.md`；
- Maker 指令没有要求跳过本地启动协议。

**停止条件**

- 找不到项目根目录；
- `AGENTS.md` 缺失、不可读取或与 Maker 指令冲突；
- Maker 要求改变项目根目录、跳过启动协议或直接进入未授权写入。

### 3.2 读取本地协议与状态入口

**输入**

- `AGENTS.md`；
- `DOCS/PROJECT_STATE.md`；
- `SPECS/ARCHITECTURE_DECISIONS.md`。

**输出**

- 当前项目名称与 Maker；
- 当前项目状态；
- 当前 Phase；
- 当前 AI 角色；
- 当前唯一主要目标；
- 当前权威文档集合；
- 当前阻塞项；
- Exit Criteria 状态；
- 下一项 Maker 决策；
- 下一轮恢复入口。

**继续条件**

- `DOCS/PROJECT_STATE.md` 存在且内部不冲突；
- 状态入口能说明当前 Phase、AI 角色、主目标和权威文档集合；
- 架构边界文档可读取，且没有发现阻止当前任务继续的硬冲突。

**停止条件**

- `DOCS/PROJECT_STATE.md` 缺失、不可读、内部冲突或指向不存在的权威文档；
- 出现多个 Active 权威来源且状态入口无法判定；
- 当前状态显示上一任务未闭环，而 Maker 没有确认本轮属于同一续作；
- Maker 指令要求覆盖现有 Phase、角色、范围、Git 规则或权威文档职责。

### 3.3 定位 Phase、角色、主目标和权威文档集合

**输入**

- `DOCS/PROJECT_STATE.md`；
- `FRAMEWORK/Phase-System.md` 中当前 Phase 规则；
- `FRAMEWORK/Role-System.md` 中当前 AI 角色与角色切换规则；
- `FRAMEWORK/Document-System.md` 中读取、创建、更新和权威来源规则；
- 状态入口列出的本轮必读和按需读取文档。

**输出**

- 本轮 AI Collaborator 身份；
- 是否允许进入 AI Builder 执行；
- 本轮必须读取的精确文档路径；
- 本轮只按需读取的文档路径；
- 本轮不得处理的范围。

**继续条件**

- 当前 Phase 规则、角色规则和文档规则可定位；
- 本轮权威文档路径存在且状态有效；
- 本轮目标能被归入当前 Phase 的 Objective 和 Conversation Contract。

**停止条件**

- 当前 Phase 或角色无法从状态入口确认；
- 任务要求提前处理其他 Phase 的目标；
- 权威文档索引指向 Superseded、Archived 或不存在的文件；
- 本轮目标会改变 Maker 决策权、项目范围、成功标准或阶段切换规则。

### 3.3.1 上下文完整性检查

**输入**

- 当前会话中 Maker 的连续纠偏；
- 本轮已读取的状态入口、Ticket、分支、Diff 和权威文档集合；
- AI 对当前 Phase、任务范围、授权状态和门槛状态的判断；
- 自动压缩、长对话恢复或跨任务续作后的摘要信息。

**输出**

- 当前上下文是否仍可安全继续；
- 是否需要触发上下文完整性门槛；
- 如需重开上下文，下一轮必须重新读取的恢复胶囊；
- 当前会话中不得继续执行的动作。

**继续条件**

- AI 能从项目文件而非聊天记忆确认当前 Phase、角色、任务、Ticket、分支、Diff 和权威文档集合；
- AI 没有把 Maker 的方向确认误判为 Git、Phase、架构写入或长期规则授权；
- 自动压缩摘要只作为入口提示，关键状态均已从权威文件重新读取；
- Maker 的纠偏没有显示 AI 已持续误解门槛、授权、任务边界或当前状态。

**停止条件**

- AI 忘记或误判当前 Phase、Ticket、分支、Diff、授权状态、权威文档或门槛状态；
- AI 引用过期信息，且该信息会影响当前判断或写入；
- Maker 连续纠正 AI 对上下文、门槛或动作边界的理解；
- AI 准备在无法确认上下文可靠性的情况下继续写入关键文档、执行 Git 动作、切换 Phase 或沉淀长期规则。

触发停止条件时，AI 不继续执行当前写入任务，应转入硬性门槛回应：建议 Maker 重开上下文，或生成只包含恢复入口、当前任务、禁止依赖聊天记忆事项和必读文档路径的最小恢复 Prompt。

### 3.4 建立本轮协作契约

**输入**

- 当前 Phase 与 AI 角色；
- Maker 本轮指令；
- 当前唯一主要目标；
- 本轮读写范围；
- 上下文完整性检查结果；
- Git 与 Diff 状态；
- 预期验证方式；
- 需要 Maker 决定的事项。

**输出**

- 面向 Maker 的协作契约，至少说明：
  - 当前项目与 Maker；
  - 当前 Phase 与 AI 角色；
  - 本轮唯一主要目标；
  - 本轮将读取、创建或更新的文档；
  - 当前不处理的事项；
  - 验证方式；
  - 写入前 Git 检查结果和实际工作分支；
  - 需要 Maker 确认的关键取舍。

**继续条件**

- Maker 已经确认必要的任务边界或任务边界可从 Active Ticket 直接获得；
- 如果需要写入，Git 状态允许在当前任务范围内继续；
- 协作契约没有把 Maker 审阅、Git 授权或 Phase 切换隐含为已完成。
- 上下文完整性检查没有触发重开上下文建议。

**停止条件**

- Maker 未确认关键取舍，且继续写入会改变权威路径、任务边界或实现深度；
- 当前只有上一任务残留 Diff，且 Maker 未确认其属于当前续作；
- 当前分支不属于本任务，或存在无关未闭环任务会污染本轮 Diff；
- 本轮目标无法保持为唯一主线。
- 上下文已经出现会影响执行安全的认知、门槛或动作偏差。

### 3.5 判断任务类型

**输入**

- Maker 本轮指令；
- 当前项目状态；
- 当前任务文档或 Ticket；
- Git 状态；
- 当前 Phase 规则。

**输出**

- 本轮任务类型之一：
  - 只读恢复或解释；
  - 文档规划或设计；
  - 文档写入；
  - Builder 执行；
  - Builder 返回后审阅；
  - Maker Git 闭环回写；
  - Phase 门检查；
  - 分叉分类；
  - 冲突处理。

**继续条件**

- 任务类型明确；
- 对应类型具备输入、输出、允许范围、禁止范围、验收标准和验证步骤；
- 如果是 Builder 执行，已有 Active Ticket 或等价执行边界。

**停止条件**

- Maker 只说“继续”，但上下文无法判断是继续写作、接受 Diff、授权 Git、切换 Phase 还是启动新任务；
- 任务文档缺少目标、非目标、范围、验收标准或验证步骤；
- 当前任务要求一次性实现完整 Skill 1.0 或超出当前 Ticket；
- 任务类型会触发硬性门槛但 Maker 尚未明确授权。

### 3.6 Phase 内协作或 Builder 执行

**输入**

- 当前 Phase 的 Objective、AI Role、Conversation Contract、Deliverables 和 Exit Criteria；
- 当前 Ticket 或本轮任务边界；
- 本轮权威文档集合；
- Maker 的新增指令。

**输出**

- 阶段内交付物草案、文档更新、代码或资产变更；
- 验证证据；
- 未解决问题；
- 是否需要 Maker 审阅的结果。

**继续条件**

- 只处理当前 Phase 和当前 Ticket 范围；
- 修改范围与允许范围一致；
- 验证方式可执行；
- 产生的新事实能写入正确权威文档。

**停止条件**

- 任务中出现未经批准的新功能、新 Phase 目标、公开发布、商业化或完整 Skill 实现要求；
- Builder 需要自行重新定义项目方向、成功标准、权威文档职责或验收方式；
- 自动化验证失败且无法在当前范围内修复；
- 需要 Maker 手工验收、方向取舍或高风险授权。

### 3.7 新事项分类

**输入**

- 协作中出现的新想法、新问题、新风险、新限制或新机会；
- 当前主目标；
- 当前 Phase 规则；
- 当前范围与非目标；
- 架构边界和硬性门槛。

**输出**

- 新事项分类：
  - 立即处理；
  - 记录后续；
  - 视为阻塞；
  - 请求 Maker 决定；
  - 拒绝展开。
- 如果需要记录，说明记录位置和未来触发条件。

**继续条件**

- 新事项不改变当前主目标，或 Maker 明确确认它应进入当前任务；
- 分类结果不会扩大当前 Ticket 的输出；
- 记录位置属于正确权威文档。

**停止条件**

- 新事项会改变项目类型、目标用户、商业化、公开发布、实现深度、Phase 或验收标准；
- 新事项与当前非目标冲突；
- 新事项会把临时偏好写成长久规则；
- 无法判断应立即处理还是记录后续。

### 3.8 触发硬性门槛

**输入**

- 即将执行的动作；
- 当前 Phase、任务状态、分支状态和 Diff 范围；
- `SPECS/ARCHITECTURE_DECISIONS.md`；
- 当前项目 Git 与 Maker 审阅规则；
- 权威文档职责。
- 上下文完整性检查结果。

**输出**

- 是否触发硬性门槛；
- 触发的门槛类型；
- 默认安全动作；
- Maker 必须确认的具体内容；
- 如果允许继续，继续前检查项。

**继续条件**

- 未触发硬性门槛；或
- Maker 已明确授权具体动作、目标对象和范围，且授权不与当前 Phase、Git 状态、权威文档或架构边界冲突。

**停止条件**

- 动作会改变 Phase、AI 角色、Exit Criteria、权威文档状态、Git 暂存区、提交历史、分支、远端、项目范围或长期架构边界；
- 授权只是方向确认、结果接受或普通“继续”，不是具体动作授权；
- 当前存在未闭环任务、无关 Diff、错误分支、未推送提交或权威文档冲突。
- 当前上下文已不可靠，继续会放大错误写入或越界执行。

### 3.9 文档写回

**输入**

- 本轮产生的新确认事实、决定、文档路径、风险、阻塞项、验证结果或下一步；
- `FRAMEWORK/Document-System.md`；
- `DOCS/04-design/DOCUMENT_WRITEBACK_DESIGN.md`；
- 当前权威文档集合；
- 当前目标文档的权威范围。

**输出**

- 更新后的正确权威文档；
- 更新后的 `DOCS/PROJECT_STATE.md`，仅保留下一轮恢复需要的当前状态；
- 未写入事项及其原因。

**继续条件**

- 写回内容属于目标文档权威范围；
- 内容对后续恢复、决策、执行、验证或复盘有明确价值；
- 没有把聊天过程、临时纠偏、AI 推断或单次提醒写成项目事实；
- 如果改变当前状态入口，`PROJECT_STATE.md` 已同步。

**停止条件**

- 无法判断写入归属；
- 写入会重复维护同一事实；
- 写入会改变长期架构边界、模板规则、Phase 规则或 Maker 决策权；
- 写入会把未确认假设写成事实。

### 3.10 Maker 审阅

**输入**

- 本轮 Diff 或交付物；
- 验证结果；
- 未解决问题；
- 当前任务验收标准；
- 需要 Maker 手工检查的内容。

**输出**

- Maker 审阅报告；
- 修改文件列表；
- 验证证据；
- 风险和未完成项；
- 当前任务状态为 Ready for Maker Review。

**继续条件**

- Maker 明确要求继续修改同一任务；
- Maker 明确接受方向但未要求 Git 闭环时，继续保留 Diff；
- Maker 明确接受里程碑 Diff 或要求稳定检查点时，进入 Git 闭环准备流程。

**停止条件**

- Maker 尚未审阅 Diff；
- Maker 只表达“继续”但未说明是继续修改、接受 Diff、授权 Git 还是切换 Phase；
- Maker 提出审阅意见，需要在当前任务范围内修正；
- Maker 请求 Git 写操作但未授权具体动作和范围。
- Maker 或 AI 发现当前上下文已经污染，需先重开或恢复。

### 3.11 状态入口收敛

**输入**

- Maker 审阅状态；
- 本轮真实完成内容；
- 验证结果；
- 未解决问题；
- 下一项 Maker 决策；
- 下一轮恢复入口；
- 当前权威文档集合变化。

**输出**

- 收敛后的 `DOCS/PROJECT_STATE.md`；
- 当前任务状态；
- 下一步；
- 下一轮恢复入口；
- 若有新增权威文档，状态入口中的精确路径和读取要求。
- 若触发上下文完整性门槛，恢复胶囊中的必读文件、当前任务和禁止依赖聊天记忆事项。

**继续条件**

- `PROJECT_STATE.md` 只记录恢复当前项目所需的有效事实；
- 当前 Phase、AI 角色、主目标、任务状态和下一步准确；
- 新增文档路径真实存在且状态正确；
- 没有把过程流水、验证细节或单次 Diff 说明写入状态入口。

**停止条件**

- 状态入口与实际 Git、文档或 Maker 决策不一致；
- 当前任务是否 Ready for Maker Review、Accepted 或 Merged 无法确认；
- 权威文档索引缺失、重复或指向错误；
- Exit Criteria 状态缺少证据。

### 3.12 下一轮恢复

**输入**

- 收敛后的 `DOCS/PROJECT_STATE.md`；
- 当前权威文档集合；
- 下一项 Maker 决策；
- 下一轮恢复入口；
- 当前 Git 和 Diff 状态。

**输出**

- 下一轮 Agent 可从项目文件恢复的入口说明；
- 本轮不处理事项；
- 需要 Maker 审阅或手工操作的内容；
- 后续任务候选，但不替 Maker 做选择。

**继续条件**

- 下一轮恢复入口指向真实文件和当前任务；
- 当前未提交 Diff 明确留给 Maker 审阅；
- 后续任务没有被自动启动。
- 若建议重开上下文，恢复胶囊只承载入口和边界，不复制未确认聊天推断。

**停止条件**

- 本轮需要 Maker 验收、手工验证或 Git 闭环；
- 下一任务依赖当前 Diff 被接受或合并；
- 存在需要 Maker 决定的范围、Phase 或权威文档问题。
- 当前上下文过载导致 AI 已无法可靠判断门槛或动作边界。

## 4. 验证场景映射

### S1 新会话恢复

**输入场景**

- 项目存在 `AGENTS.md` 与 `DOCS/PROJECT_STATE.md`；
- Maker 要求继续当前项目。
