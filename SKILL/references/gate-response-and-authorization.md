# Gate Response and Authorization Reference

> Status: Draft
> Owner Ticket: `DOCS/05-planning/TICKETS/TICKET-R2-02-gate-response-and-authorization.md`
> Scope: Project Incubator Skill 1.0 的门槛回应与 Maker 明确授权判断参考。
> Last Updated: 2026-07-25

## 1. 文档职责

本文定义当主运行链路或硬门槛矩阵发现风险时，AI 应如何向 Maker 回应，以及 Maker 的授权必须包含哪些字段才足以继续执行。

本文只说明回应结构和授权字段，不负责：

- 设计 UI；
- 解析命令语法；
- 执行 Git 闭环；
- 将含糊表达自动解释为授权；
- 改写 `AGENTS.md`、`FRAMEWORK/` 或架构决策。

## 2. 回应原则

门槛回应必须简短、可行动，并保留 Maker 的决定权。

AI 不应把门槛回应写成长篇解释，也不应替 Maker 选择方向。回应的核心是说明：

- 风险结果是什么；
- 默认不会执行什么；
- 可以先做哪些安全动作；
- 如果 Maker 要继续，需要明确授权什么；
- 获得授权后仍需复核哪些条件。

## 3. 标准回应结构

当门槛触发时，AI 使用以下结构回应：

1. **风险结果**：说明继续执行会影响的对象或边界。
2. **默认边界**：说明 AI 默认不会直接执行的动作。
3. **安全替代**：提供不改变关键状态的下一步。
4. **所需授权**：列出 Maker 如要继续必须确认的字段。
5. **执行前复核**：说明即使授权明确，AI 也会先复核的状态。

推荐句式：

```text
这会影响 [风险对象或边界]。我默认不会直接执行 [受限动作]。
我可以先 [安全替代动作]。
如果你要我继续执行，请明确确认：[动作]、[对象]、[范围]。
获得确认后，我会先复核 [必要状态]，再继续。
```

## 4. 明确授权字段

所有需要越过门槛的授权至少包含：

| 字段 | 含义 |
| --- | --- |
| 动作 | Maker 要 AI 做什么，例如创建分支、修改状态、进入下一 Phase、写入某个权威文档 |
| 对象 | 动作作用于哪个分支、文件、文档、Ticket、Phase 或规则 |
| 范围 | 本次授权覆盖到什么边界，哪些内容不包含在内 |

在高风险场景中，还应包含：

| 字段 | 适用场景 |
| --- | --- |
| 预期结果 | Phase 切换、架构决策、任务范围变化 |
| 停止条件 | Git 操作、冲突处理、验证失败、远端状态异常 |
| 写入位置 | 权威文档、Skill reference、模板、`PROJECT_STATE.md` |
| 长期适用范围 | 架构决策候选、纠偏沉淀、Framework 或 Skill 长期规则 |

## 5. 门槛类型回应

| 门槛 | 风险结果 | 默认不执行 | 安全替代 | 需要 Maker 明确确认 |
| --- | --- | --- | --- | --- |
| Git 门槛 | 改变历史、分支状态或远端状态 | 暂存、提交、推送、合并、删除分支、重写历史 | 只读检查、列出命令清单、说明停止点 | Git 动作、目标分支、文件范围、远端范围、停止条件 |
| Phase 门槛 | 改变项目阶段、角色和必读集合 | 直接进入下一 Phase 或回退 Phase | 做 Exit Criteria 检查并列出缺口 | 目标 Phase、切换方向、缺口处理方式、状态回写范围 |
| 权威文档门槛 | 改变事实来源或文档所有权 | 静默创建、迁移、复制或覆盖权威来源 | 指出冲突、建议候选写入位置 | 目标文档、写入事实、替代或补充关系、索引更新 |
| 范围门槛 | 把当前 Ticket 扩展成新任务或新里程碑 | 混入 R2/R3/R4 或实现完整 Skill | 登记为后续 Ticket 或留在当前 Draft 内修正 | 新范围、是否仍属当前任务、成功标准影响 |
| Builder 交接门槛 | 在任务字段不完整时进入执行 | 开始写入或实现 | 补齐缺口清单、请求 Maker 或上游文档确认 | Ticket 路径、输出物、验收标准、验证步骤 |
| 未闭环任务门槛 | 把上一个任务 Diff 带入无关任务 | 创建新任务分支或开始无关写入 | 报告当前 Diff 和分支状态 | 当前 Diff 是否属于续作、允许继续的任务范围 |
| 上下文完整性门槛 | 在上下文过载、压缩污染或连续纠偏后继续关键动作 | 继续关键写入、Git、Phase、架构写入或长期规则沉淀 | 建议重开上下文、输出最小恢复胶囊、只做只读恢复 | 是否重开上下文、当前允许继续任务、必读恢复文件、当前 Diff 处理方式 |
| Prompt 搬运门槛 | 可复制 Prompt 正文携带项目状态、已完成历史、权威文档集合、Git 信息或推荐依据 | 直接输出该 Prompt 正文 | 拆分 Prompt 外说明与只含任务 delta 的 Prompt 正文；重写命中黑名单的正文 | 是否明确要求本次 Prompt 自包含项目状态，以及该例外的对象和范围 |
| 纠偏沉淀门槛 | 把单次纠偏写成长期强规则 | 直接写入长期规则、模板规则或架构决策 | 修正当前 Draft、删除不当内容、登记后续判断 | 纠偏内容、长期范围、现有边界覆盖判断、写入位置、原则表述 |
| 架构决策候选门槛 | 改变长期架构约束 | 直接更新 Architecture Decision | 写成候选问题或请求决策 | 决策内容、适用范围、替代关系、受影响文档 |

## 6. 不足授权示例

以下表达不足以越过门槛：

| Maker 表达 | 不足原因 | AI 默认回应 |
| --- | --- | --- |
| “继续” | 没有动作、对象和范围 | 继续当前已授权范围内的下一步；若下一步触发门槛，先请求明确授权 |
| “没问题” | 只能表示内容方向可接受，不能代表 Git、Phase 或架构授权 | 记录为当前内容方向确认，不执行受限动作 |
| “好的” | 未说明具体授权对象 | 只执行不越过门槛的安全动作 |
| “确认” | 缺少确认的具体内容 | 复述需要确认的字段并等待 Maker 明确 |
| “帮我合并” | Git 动作、分支、合并方式和停止条件不明确 | 先列出当前分支、文件范围和建议闭环命令，等待明确授权或 Maker 手动执行 |
| “进入下一阶段” | 未完成 Phase gate 检查与缺口处理决定 | 先输出 Exit Criteria 检查，再等待 Maker 决定 |
| “把这个写进架构决策” | 未确认长期边界、写入位置和与既有决策关系 | 先要求 Maker 确认长期适用范围和权威位置 |
| “上下文太乱了但继续吧” | 已提示上下文完整性风险，且未确认安全恢复方式 | 建议重开上下文或只输出最小恢复胶囊，不继续关键写入 |
| “写完整一点，把背景也带上” | 可能要求把可由项目文件恢复的状态搬进 Prompt；未说明是任务特有背景还是项目状态 | Prompt 外说明可解释背景；Prompt 正文仍只写本任务 delta，除非 Maker 明确要求自包含项目状态例外 |
| “你看着办” | 将方向决定转移给 AI | 给出方案和推荐，但不替 Maker 作关键决定 |

## 7. 安全替代动作

当授权不足时，AI 可以继续执行以下安全动作：

- 只读检查当前状态、分支、Diff 或文档；
- 汇总风险和可选方案；
- 提供 Maker 手动执行命令清单；
- 输出最小恢复胶囊，驱动新会话重新读取权威文件；
- 对当前 Draft 内的不当表述做局部修正；
- 把越界内容登记为后续 Ticket 或待确认问题；
- 回写 `PROJECT_STATE.md` 中已确认且不改变方向的状态事实。

安全替代动作不得绕过门槛。如果替代动作本身会修改权威规则、Git 状态、Phase 状态或任务范围，仍需重新请求明确授权。

## 8. 执行前复核

即使 Maker 已明确授权，AI 在执行受限动作前仍需复核：

- 当前 `DOCS/PROJECT_STATE.md` 是否仍显示同一 Phase、角色和任务；
- 当前分支和 Diff 是否仍属于本任务；
- 目标文档是否仍是有效权威来源；
- 授权是否包含动作、对象和范围；
- 当前上下文是否仍可靠，是否需要重开上下文；
- 验证步骤是否仍可执行；
- 是否出现新的冲突、缺失文件、未闭环任务或远端异常。

如果复核失败，AI 必须停止执行受限动作，报告失败点，并回到门槛回应结构。

## 9. 验证场景映射

| 场景 | 预期行为 |
| --- | --- |
| S2：Maker 只说“继续” | 仅在当前已授权范围内推进；如果下一步触发 Git、Phase、权威文档或范围门槛，判断为授权不足 |
| “帮我合并” | 要求明确 Git 动作、目标分支、文件范围、远端范围和停止条件；默认只提供命令清单 |
| “进入下一阶段” | 先执行 Phase Exit Criteria 检查，列出缺口和风险，不直接切换 |
| “把这个写进架构决策” | 要求 Maker 确认长期适用范围、现有决策关系和写入位置 |
| 上下文过载或压缩污染 | 停止关键动作，建议重开上下文；输出只包含必读文件、当前任务、Diff 处理和禁止依赖聊天记忆事项的恢复胶囊 |
| 生成下一任务 Prompt | 可复制 Prompt 正文不得包含项目状态、已完成历史、权威文档集合、Git 信息或推荐依据；如命中则重写，只把解释放在 Prompt 外说明 |

## 10. 最小恢复胶囊回应

当上下文完整性门槛触发时，AI 使用以下短回应驱动 Maker 重开上下文：

```text
当前上下文已经出现门槛、状态或动作判断偏差。继续在本对话内推进有污染风险。
我建议停止当前关键写入，保留现有 Diff，并由 Maker 新开上下文。

新上下文启动时请按最小必要粒度重新建立权威上下文：
- 启动协议：全量读取 `AGENTS.md`；
- 状态入口：全量读取 `DOCS/PROJECT_STATE.md`；
- 架构边界：按启动协议与当前门槛需要读取 `SPECS/ARCHITECTURE_DECISIONS.md`；
- 当前规则：按 `PROJECT_STATE.md` 指向读取当前 Phase / Role / Document 相关章节；
- 当前任务边界：全量读取当前 Ticket 或等价任务文档；
- 当前产物草案：只读取本轮任务涉及的 Skill reference。

本轮只应继续：[当前任务或审阅点]。
不得依赖聊天记忆判断：当前 Phase、任务范围、Maker 是否授权 Git / Phase / 架构写入、当前 Diff 是否可继续、门槛是否已解除。
```

恢复胶囊只承载入口和边界，不复制完整聊天历史，不包含未经项目文件验证的推断。

## 11. 后续消费方式

最终 `SKILL.md` 可把本文作为门槛触发后的回应参考：

- 主运行链路发现门槛后，转入本文的标准回应结构；
- 硬门槛矩阵提供触发条件，本文提供回应方式和授权字段；
- R3 Builder handoff 可复用本文的授权字段检查；
- 如后续需要把部分回应规则固化进 `AGENTS.md` 或模板，应另开 Build Ticket 并经 Maker 明确确认。
