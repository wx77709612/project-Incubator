# Task Type And Writeback Reference

用于 Project Incubator Skill 判断本轮任务类型、读取粒度、写回触发条件、状态入口收敛和下一轮恢复入口。

读取时机：当本轮涉及任务分类、文档写回、状态收敛、上下文恢复、Maker 任务 Prompt 或 Builder 返回后的写回判断时读取。

相关 Skill 资产：

- `references/main-runtime-chain.md`
- `references/hard-gate-matrix.md`
- `references/gate-response-and-authorization.md`

## 1. 文档职责

本文档承载 R1-02 的 Build 输出：定义 Skill 1.0 在主运行链路中如何判断本轮任务类型、如何决定读取哪些文档内容、何时写回文档、写回到哪里，以及何时不写回。

本文档不是最终 `SKILL.md`，不创建脚本，不创建模板，不修改 `PROJECT_STATE.md` 生产模板，也不改变既有文档系统规则。它只把当前已确认的写回设计和状态入口设计转写为未来 Skill 可消费的 reference。

## 2. 输入来源与读取粒度

### 2.1 输入来源

任务类型判定中的“输入”分为两类：

| 输入类别 | 来源 | Maker 是否需要手动提供 |
| --- | --- | --- |
| Maker 本轮指令 | Maker 在当前会话中的新增请求、确认或限制 | 需要 |
| 项目文件输入 | 当前项目工作区内的 `AGENTS.md`、`DOCS/PROJECT_STATE.md`、Framework、SPECS、Ticket、Phase 文档和 Skill references | 不需要，Agent 应自行读取 |

Maker 通常只需要提供本轮指令和关键决策。项目文件内容应由 Agent 按启动协议、状态入口和任务类型自行读取。只有当文件缺失、路径冲突、状态不清或继续会改变边界时，Agent 才请求 Maker 决定。

### 2.2 读取粒度

读取粒度按文档职责和任务类型决定：

| 文档或输入 | 默认读取粒度 | 说明 |
| --- | --- | --- |
| Maker 本轮指令 | 全量理解 | 本轮指令是任务增量输入，必须完整考虑 |
| `AGENTS.md` | 全量读取 | 本地启动、Git、写入和会话结束协议高权威且高频使用 |
| `DOCS/PROJECT_STATE.md` | 全量读取 | 状态入口负责恢复当前 Phase、角色、目标、权威文档集合和下一步 |
| `SPECS/ARCHITECTURE_DECISIONS.md` | 当前仓库按启动协议读取；未来 Skill 可先读职责与索引，再按触发边界读取对应 Decision 正文 | 本文不改变当前 `AGENTS.md` 要求 |
| `FRAMEWORK/Phase-System.md` | 当前 Phase 章节为主 | 只有阶段定位失败、跨 Phase 决策或 Framework 变更时才扩大读取 |
| `FRAMEWORK/Role-System.md` | 当前角色、AI Collaborator / Builder 边界和角色切换规则为主 | Builder 交接、返回审阅或角色冲突时读取相关章节 |
| `FRAMEWORK/Document-System.md` | 文档读取、创建、更新、权威来源和当前任务涉及的文档类型章节为主 | 文档写入任务通常需要读得更充分 |
| 当前 Ticket | 全量读取 | Ticket 是 Builder 或执行任务边界 |
| 当前待修改文档 | 全量读取 | 修改前必须理解目标文档权威范围、结构和现有内容 |
| 状态入口列出的必读文档 | 按状态入口要求读取 | 必读不等于永远复制全文到输出 |
| 状态入口列出的按需文档 | 仅在本轮任务涉及对应事实、边界或验证时读取 | 不通过目录扫描代替状态索引 |
| Skill reference | 按本轮任务需要读取相关 reference | 最终 `SKILL.md` 应引用或压缩 reference，不复制全部细节 |

### 2.3 读取失败处理

读取失败时应先判断失败类型：

- 缺失或不可读：报告缺口，停止阶段推进；
- 路径冲突：列出冲突来源，等待 Maker 决定；
- 读取粒度不足：补读相关章节或全文，并说明原因；
- 文档状态无效：不自行选择方便版本；
- 当前任务不需要：不读取，不把按需文档提升为默认必读。

### 2.4 产物承载类型判定

写入任何产物前，先判定产物承载类型，再套用对应写法。承载类型优先于“这是 Markdown / 文档”这类表层格式。

常见承载类型包括：

- 项目 Phase 文档：按 `DOCS/<phase>/` 文档规则写入，可以使用项目文档元数据；
- 项目状态入口：按 `DOCS/PROJECT_STATE.md` 状态入口规则写入；
- Skill runtime reference：按运行时 reference 规则写入，保留用途、读取时机和相关 Skill 资产，不套项目文档状态表；
- Skill asset / template：按资产或模板实例化规则写入，保留占位字段、路径域和必要删除说明；只有会实例化为目标项目 `DOCS/` 权威文档的模板才使用项目文档元数据；
- 目标项目实例文件：按目标项目本地协议写入；
- 代码 / 脚本 / 配置：按对应技术格式写入，不套 Markdown 文档规则；
- Prompt 正文：只承载任务 delta，不搬运项目状态、Git 历史或权威文档集合。

如果无法判定承载类型，或准备把一种承载物的格式规则套到另一种承载物上，触发 `hard-gate-matrix.md` 的承载类型错位门槛。

## 3. 任务类型判定表

| 任务类型 | 判定信号 | 是否允许写回 | 默认写回位置 | 何时不写回 |
| --- | --- | --- | --- | --- |
| 只读任务 | Maker 要求解释、总结、检查、查看状态，且不改变项目事实 | 通常不写回 | 无；必要时只在对话中报告 | 没有新事实、路径、状态、阻塞、决定或下一步变化 |
| 文档规划任务 | Maker 要求设计、规划、拆 Ticket、定义验收或比较方案 | 允许 | 当前 Phase 文档、Planning 文档或 Ticket；如影响恢复再更新 `PROJECT_STATE.md` | 只是临时讨论、未确认方案或 AI 建议 |
| 文件写入任务 | Maker 授权创建或修改项目文档、代码或资产 | 允许 | 被授权的目标文件；如路径、状态或下一步变化再更新 `PROJECT_STATE.md` | 修改不影响恢复入口，且目标文件已完整承载结果 |
| Builder 执行任务 | 当前 Phase 允许执行，且已有目标、非目标、范围、验收标准和验证步骤 | 允许 | 任务产物、验证结果所在文档；必要时更新 `PROJECT_STATE.md` | Ticket 不完整、验证未执行或 Builder 需要重新定义方向 |
| Builder 返回后审阅 | Builder 报告完成、失败或需要审阅 | 允许 | 审阅结果、验证证据或状态入口；必要时进入 Maker Review | 只是口头状态、没有证据或 Maker 尚未审阅 |
| 阶段门检查 | Maker 想推进、返回、跳过、暂停或归档 Phase | 允许但受门槛约束 | `PROJECT_STATE.md` 和当前 Phase 交付物状态；仅 Maker 决定后写入 Phase 变化 | 只有阶段愿望，没有 Maker 明确阶段决定 |
| Git 闭环回写 | Maker 报告已提交、推送、合并、清理分支或回到 `main` | 允许，但先只读 Git 检查 | `PROJECT_STATE.md` 中任务状态、分支闭环、下一步和恢复入口 | Git 状态无法验证、远端不同步或闭环结果不清 |
| Maker 任务 Prompt 生成 | Maker 要求生成下一任务、新会话或交接 Prompt | 允许按协议读取模板；必要时先状态回写 | Prompt 输出在对话；若状态已变化则先更新 `PROJECT_STATE.md` | 未完成 Git 闭环回写，或 Prompt 正文未通过 Prompt 生成卫生检查 |
| 上下文恢复或重开建议 | 长对话、自动压缩或连续纠偏后，AI 的 Phase、Ticket、Git、授权、权威文档或门槛判断出现偏差 | 通常不写回；只有恢复入口、阻塞或下一步变化时写回 | 对话中输出最小恢复 Prompt；必要时更新 `PROJECT_STATE.md` 的阻塞项、下一步或恢复入口 | 只是临时澄清，且项目文件中的状态、任务和下一步没有变化 |
| 分叉处理 | 出现新想法、新范围、新阻塞、新风险或跨 Phase 请求 | 视分类结果而定 | 立即处理、后续记录、阻塞项、Maker 决策或拒绝展开对应位置 | 新事项不影响当前主线且没有后续消费价值 |
| 冲突处理 | 权威路径缺失、多 Active 来源、状态与文档冲突、架构边界冲突 | 允许记录真实阻塞 | `PROJECT_STATE.md` 阻塞项或受影响权威文档；修复需 Maker 决定 | 冲突只是读取误差，补读后已澄清且无状态变化 |

### 3.1 Maker 任务 Prompt 生成卫生检查

Maker 任务 Prompt 生成必须拆成两个输出区：

- Prompt 外说明：可以说明推荐理由、状态判断和为什么建议下一任务；
- Prompt 正文：只承载 Maker 要发给新任务 Agent 的本次任务 delta。

Prompt 正文只允许包含：

- 本任务目标；
- 本任务特有边界、风险或限制；
- 本任务需要 Maker 确认、接受或验收的事项；
- 本任务完成后的 Diff、验证与状态回写要求。

Prompt 正文不得包含：

- 当前 Phase、当前 AI 角色或项目状态；
- 已完成内容、当前基线、权威文档集合或读取清单；
- Git 分支、提交号、合并状态、远端状态或历史；
- 应由 `AGENTS.md`、`DOCS/PROJECT_STATE.md` 和任务 Prompt 模板自动恢复的上下文；
- 只用于解释推荐理由的状态依据，例如“基于已合并的 R1-R3 references”。

检查流程：

1. 先写 Prompt 外说明；
2. 再写可复制的 Prompt 正文；
3. 对 Prompt 正文执行白名单与黑名单检查；
4. 如果 Prompt 正文命中黑名单，则该 Prompt 不合格，AI 必须删除黑名单内容或移到 Prompt 外说明后重写；
5. 不要求 Maker 自行筛掉 Prompt 正文中的状态搬运内容。

## 4. 写回触发条件

### 4.1 必须考虑写回的变化

出现以下变化时，必须判断是否写回：

- 当前 Phase 变化；
- 当前 AI 角色变化；
- 当前主要目标变化；
- 当前任务状态变化；
- 阶段交付物路径或状态变化；
- 当前权威文档集合变化；
- Maker 作出影响后续恢复的决定；
- 出现或解除真实阻塞；
- 验证结果影响任务是否可继续；
- 下一项决定变化；
- 下一轮恢复入口变化；
- Git 闭环状态影响任务状态。
- 上下文完整性风险已经影响当前任务是否能安全继续。

### 4.2 不应写回的内容

以下内容默认不写入权威文档，尤其不写入 `PROJECT_STATE.md`：

- 聊天过程；
- AI 的临时解释；
- Maker 某次反馈原文；
- 单次 Diff 审阅细节；
- 验证过程流水；
- 可由 Git 历史追溯的过程；
- 未经 Maker 确认的推断；
- 低复用的单次纠偏；
- 与当前 Phase 或 Ticket 无关的新想法。
- 自动压缩摘要中的未验证推断。

### 4.3 写回位置选择

写回位置按权威归属选择：

| 承载类型或变化类型 | 默认写回位置 |
| --- | --- |
| 项目 Phase 文档 | 对应 `DOCS/<phase>/` 文档 |
| 项目状态入口 | `DOCS/PROJECT_STATE.md` |
| Skill runtime reference | Skill 资产路径 `references/` 中对应 reference |
| Skill asset / template | Skill 资产路径 `assets/` 中对应模板或资产 |
| 目标项目实例文件 | 目标项目路径中的对应文件 |
| 代码 / 脚本 / 配置 | 被授权的技术文件路径 |
| Prompt 正文 | 默认只输出在对话中；不得写入项目状态 |
| 当前项目状态、主目标、任务状态、阻塞项、下一步、恢复入口 | `DOCS/PROJECT_STATE.md` |
| 阶段内设计、规划、验证或执行结论 | 对应 Phase 文档或当前 Ticket |
| Skill 运行规则细节 | `SKILL/references/` 中对应 reference |
| 长期架构边界候选 | 先提出候选，Maker 确认后再写入 `SPECS/ARCHITECTURE_DECISIONS.md` |
| 本地 Agent 执行协议长期变化 | 先说明影响，Maker 确认后再考虑 `AGENTS.md` |
| 模板结构变化 | 后续模板任务或 `TEMPLATES/`，不在 R1-02 中修改 |
| 上下文恢复胶囊 | 默认在对话中输出；只有影响下一轮恢复时才收敛进 `PROJECT_STATE.md` |

## 5. `PROJECT_STATE.md` 收敛检查

更新 `DOCS/PROJECT_STATE.md` 前，应逐项检查：

- 是否仍只有一个当前主要目标；
- 当前 Phase 与当前 AI 角色是否匹配；
- 当前任务状态是否反映真实工作状态；
- 当前阶段交付物是否只列有效路径和状态；
- 当前权威文档集合是否使用精确路径；
- 未确认事项是否仍影响后续恢复、决策或规划；
- 阻塞项是否是真阻塞；
- 下一项决定是否需要 Maker 行动；
- 下一步是否可执行；
- 下一会话恢复入口是否指向真实文件和当前任务；
- 是否出现流水账、纠偏留痕或重复维护事实。

如果检查失败，先修正状态入口，不继续推进后续任务。

## 6. 下一轮恢复入口检查

每次收尾前，应检查下一轮恢复入口是否满足：

- 下一个 Agent 能从 `AGENTS.md` 与 `DOCS/PROJECT_STATE.md` 恢复；
- 下一步指向当前真实任务，而不是过期任务；
- 新增文档已经进入权威文档集合或说明为何不需要；
- 当前 Diff、任务状态和 Maker 决定一致；
- 若任务处于 Ready for Maker Review，明确等待 Maker 审阅；
- 若任务处于 Accepted，明确是否等待 Git 稳定检查点或继续同一里程碑；
- 不自动启动后续无关任务。

### 6.1 最小恢复胶囊

当上下文完整性门槛触发，且 Maker 需要重开上下文时，AI 输出的恢复胶囊只承载新会话恢复所需入口，不搬运完整聊天过程。

恢复胶囊应包含：

- 需要重新建立的恢复锚点及其最小读取粒度：
  - 启动协议：全量读取 `AGENTS.md`；
  - 状态入口：全量读取 `DOCS/PROJECT_STATE.md`；
  - 架构边界：按启动协议与当前门槛需要读取 `SPECS/ARCHITECTURE_DECISIONS.md`；
  - 当前规则：按 `PROJECT_STATE.md` 指向读取当前 Phase / Role / Document 相关章节；
  - 当前任务边界：全量读取当前 Ticket 或等价任务文档；
  - 当前产物草案：只读取本轮任务涉及的 Skill reference；
- 当前只允许继续的任务或审阅点；
- 当前 Diff 是否保留给 Maker 审阅；
- 不得依赖聊天记忆判断的事项：当前 Phase、任务范围、Maker 是否授权 Git / Phase / 架构写入、当前 Diff 是否可继续、门槛是否已解除；
- 本轮明确不处理的范围。

恢复胶囊不应包含：

- 未经项目文件验证的聊天摘要；
- AI 对 Maker 意图的推断；
- 未确认的授权；
- 可由权威文件重新读取的长正文；
- 与下一轮恢复无关的过程细节。

## 7. 验证场景映射

### S2 Maker 说“继续”

**输入场景**

- 当前 R1-01 Diff 已被 Maker 表达“没问题”；
- Maker 后续说“继续同一里程碑范围”。

**预期判定**

- 任务类型为当前里程碑范围内的后续文件写入任务；
- 不是 Git 授权；
- 不是 Phase 切换；
- 不是无关新任务。

**写回规则**

- 将当前任务状态从 Ready for Maker Review 收敛为 Accepted；
- 将下一步改为继续同一里程碑范围内的后续 Ticket；
- 不提交、不推送、不合并。

### S5 新想法出现

**输入场景**

- 在 R1 或 Phase 6 中出现 Skill 发布、商业化、脚本化全部检查或完整模板体系想法。

**预期判定**

- 任务类型为分叉处理；
- 分类为记录后续、请求 Maker 决定或拒绝展开；
- 不进入当前 R1-02 主线。

**写回规则**

- 只有影响后续恢复或决策时，才写入 `PROJECT_STATE.md` 的未确认事项或下一步；
- 如果只是临时讨论，不写回；
- 不修改 Framework 或模板。

### 文档写入完成场景

**输入场景**

- R1-02 产出 `SKILL/references/task-type-and-writeback.md`；
- 验证发现该文档覆盖任务类型和写回规则。

**预期判定**

- 任务类型为文件写入任务；
- 允许写入新 Skill reference；
- 允许更新 `PROJECT_STATE.md` 中的交付物路径、权威文档集合、任务状态和下一步。

**写回规则**

- `SKILL/references/task-type-and-writeback.md` 承载规则正文；
- `PROJECT_STATE.md` 只收敛路径、状态、下一步和恢复入口；
- 不把验证过程细节写入状态入口。

### 上下文恢复场景

**输入场景**

- 长对话或自动压缩后，AI 把过期信息当作当前事实；
- Maker 指出 AI 的门槛、授权或任务边界判断已经偏离；
- 当前任务仍有未提交 Diff。

**预期判定**

- 任务类型为上下文恢复或重开建议；
- 不是继续写入授权；
- 不是 Git 授权；
- 不是 Phase 切换；
- 不在污染上下文中继续关键动作。

**写回规则**

- 默认在对话中输出最小恢复胶囊；
- 如果恢复入口、阻塞项或下一项 Maker 决策发生变化，才更新 `PROJECT_STATE.md`；
- 不把自动压缩摘要或未验证聊天记忆写入权威文档；
- 不提交、不推送、不合并。

### Maker 任务 Prompt 卫生场景

**输入场景**

- Maker 已完成某个里程碑 Git 闭环；
- Maker 要求 AI 生成下一任务 Prompt；
- AI 可以在 Prompt 外说明中解释推荐下一任务的理由。

**预期判定**

- 任务类型为 Maker 任务 Prompt 生成；
