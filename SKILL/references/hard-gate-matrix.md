# Hard Gate Matrix Reference

用于 Project Incubator Skill 判断哪些动作必须暂停、说明风险、采用默认安全动作，并等待 Maker 明确确认。

读取时机：当本轮可能改变 Phase、Git 状态、权威文档、项目范围、Builder 交接、上下文完整性、输出约束、产物承载类型或长期规则时读取。

相关 Skill 资产：

- `references/main-runtime-chain.md`
- `references/task-type-and-writeback.md`
- `references/gate-response-and-authorization.md`

## 1. 文档职责

本文档承载 R2-01 的 Build 输出：把 Project Incubator Skill 1.0 中必须暂停、说明风险并等待 Maker 明确确认的高风险结果整理为硬性门槛矩阵。

本文档不脚本化门槛检查，不替 Maker 作方向决定，不修改 `SPECS/ARCHITECTURE_DECISIONS.md`，也不把普通提醒升级为门槛。后续 R2-02 可以基于本文档定义门槛触发后的标准回应和授权字段。

## 2. 硬性门槛原则

硬性门槛按行动可能造成的结果触发，而不是按 Maker 的具体措辞触发。

当本轮行动可能造成以下结果之一时，AI 必须暂停：

- 改变 Phase、AI 角色、Exit Criteria 或阶段状态；
- 改变 Git 暂存区、提交历史、分支、远端或工作区保存边界；
- 改变权威文档状态、权威路径、职责归属或长期规则；
- 扩大项目类型、目标用户、商业化、公开发布、团队协作或实现深度；
- 在 Builder 任务边界不足时进入执行；
- 在未闭环 Diff、未推送提交、错误分支或状态入口冲突下启动无关新写入；
- 在上下文过载、自动压缩污染或连续纠偏后仍继续关键写入或高风险动作；
- 在写入回复、Markdown 正文、Skill 入口、reference、模板、项目文档或其他交付物前，未确认已接入项目的本地协议，或未接入项目的接入流程、语言、格式、正文风格、内容承载、读写范围和工具边界；
- 在写入前未确认产物承载类型，或准备把项目 Phase 文档、项目状态入口、Skill runtime reference、Skill asset / template、目标项目实例文件、代码 / 脚本 / 配置、Prompt 正文之间的格式规则互相套用；
- 在 Maker 提出质疑、反驳、要求解释原因，或挑战协作方式、门槛、长期规则时，AI 准备直接修改规则而未先做正反判断；
- 把单次纠偏、临时偏好、一次错误或当前任务限制沉淀为长期规则；
- 将候选长期架构边界直接写入 Architecture Decisions。

Maker 的“继续”“没问题”“接受”“下一步”“建立检查点”等表达，只能作为任务类型判定输入，不能自动转化为 Git、Phase、权威文档、范围或 Builder 执行授权。

## 3. 门槛矩阵

| 门槛类型 | 触发结果 | 默认安全动作 | Maker 必须确认 | 允许继续条件 | 失败或冲突处理 |
| --- | --- | --- | --- | --- | --- |
| Phase 门槛 | 改变当前 Phase、AI 角色、Exit Criteria、阶段状态或阶段目标 | 停止阶段推进，输出当前 Phase Objective、Deliverables、Exit Criteria、缺口、风险和可选下一步 | 是否切换、返回、跳过、暂停或归档；是否接受带风险推进；是否更新 `DOCS/PROJECT_STATE.md` | Maker 明确作出阶段决定，且状态入口可同步更新 | 不更新 Phase；维持当前角色；把问题记录为下一项 Maker 决策或阻塞 |
| Git 门槛 | 改变分支、暂存区、提交、推送、合并、远端、历史或分支清理 | 只做只读 Git 检查，或提供 Maker 手动命令清单 | 是否授权 AI 执行具体 Git 动作；目标分支、文件范围、提交/推送/合并对象；是否允许高风险操作 | Maker 明确授权具体动作、对象和范围，且执行前 Git 检查通过 | 不执行 Git 写操作；报告状态和风险；需要时等待 Maker 手动闭环 |
| 权威文档门槛 | 改变文档状态、权威路径、职责归属、模板实例化规则或长期文档规则 | 报告受影响文档、当前权威来源、拟变更内容和下游影响 | 是否确认权威来源改变；是否替代、迁移、归档或新增权威文档；是否更新状态索引 | Maker 明确确认权威变化，且所有受影响索引可一致更新 | 不自行选择方便版本；把冲突列为阻塞；停止阶段推进 |
| 范围门槛 | 扩大项目类型、目标用户、商业化、公开发布、团队协作、完整实现或验证深度 | 拒绝静默扩大，按分叉处理分类为后续、阻塞、请求决定或拒绝展开 | 是否改变项目范围、目标用户、公开程度、商业化目标或实现深度；是否进入新 Phase 或新任务 | Maker 明确确认范围变化，并说明当前任务是否纳入或后续处理 | 不加入当前 Ticket；必要时记录为未确认事项或后续任务 |
| Builder 交接门槛 | 任务缺少目标、非目标、输入、输出、允许/禁止范围、验收标准、验证步骤或完成后更新项 | 不交给 Builder，回到 Planning 或当前 Ticket 补齐边界 | 是否补齐缺失字段；是否仍允许 Builder 执行；是否调整 Ticket 边界 | Ticket 或等价执行文档完整，且当前 Phase 允许 Builder 执行 | Builder 不启动；缺口写回当前 Ticket 或下一步 |
| 未闭环任务门槛 | 存在未提交 Diff、未推送提交、无关分支、错误工作分支、远端不同步、上一任务状态不清或状态入口冲突 | 停止无关新写入任务，报告 Git / Diff / 状态缺口 | 当前 Diff 是否属于同一续作；是否先建立稳定检查点；是否允许继续同一里程碑范围 | Maker 明确确认续作范围或完成必要 Git / 状态闭环，且当前分支与任务一致 | 不创建无关分支；不混入新任务；必要时只做只读检查 |
| 上下文完整性门槛 | 长对话、自动压缩或连续纠偏后，AI 已误判或无法确认 Phase、Ticket、Git、授权、权威文档、门槛状态或当前动作边界 | 停止关键写入和高风险动作；建议重开上下文；输出最小恢复胶囊 | 是否重开上下文；当前允许继续的任务或审阅点；恢复时必须读取的文件；是否只保留 Diff 供审阅 | Maker 重开上下文或明确要求在当前会话只做低风险修正，且 AI 已从权威文件重新确认当前状态 | 不继续关键写入、Git、Phase、架构写入或长期规则沉淀；只保留恢复入口、阻塞或下一步 |
| 本地协议与输出约束门槛 | 通用 Skill 写法、外部工具习惯、模型惯性或旧上下文可能覆盖已接入项目的本地 `AGENTS.md`、状态入口，或未接入项目的接入流程、语言要求、Markdown 正文规范、内容承载、读写范围或工具边界 | 停止写入；已接入项目重新读取本地协议和目标文档；未接入项目读取接入流程并确认写入授权；按适用规则重写或报告冲突 | 哪个本地规则或接入流程适用；是否允许例外；例外作用于哪些输出、文件、字段和范围 | 已接入项目的本地协议已确认，或未接入项目的接入流程与 Maker 写入授权已确认；输出语言、正文规范、承载规则和工具边界已应用；或 Maker 明确批准具体例外 | 不按通用默认写法继续；不把 metadata、代码、文件名的英文许可扩展为 Markdown 正文英文许可；不把工具通用能力解释为当前项目授权；不静默覆盖本地规则；不读取或要求不存在的本地协议 |
| 承载类型错位门槛 | 未先判定产物承载类型，或把一种承载物的格式规则套到另一种承载物上，例如把项目 Phase 文档状态表套到 Skill runtime reference，或把项目状态搬进 Prompt 正文 | 停止写入；先声明产物承载类型、适用写法、路径域和禁止套用的规则 | 产物属于项目 Phase 文档、项目状态入口、Skill runtime reference、Skill asset / template、目标项目实例文件、代码 / 脚本 / 配置还是 Prompt 正文；适用哪套规则；哪些当前项目规则不得套用 | 承载类型、目标路径域、适用规则和禁止套用规则已明确，且 Maker 未要求例外；或 Maker 明确批准具体例外 | 不把当前项目文档结构套到 Skill runtime reference、不会实例化为目标项目 `DOCS/` 权威文档的 Skill asset / template、代码、配置或 Prompt；不把 Skill 资产路径当成目标项目路径；不把目标项目状态当成 Skill 自身状态 |
| 质疑回应与非迎合门槛 | Maker 提出质疑、反驳、要求解释原因，或挑战协作方式、门槛、长期规则，AI 准备直接顺着质疑修改规则 | 暂停修改；先从“合理时如何改”和“不合理时为什么不改”两面判断；说明依据和建议 | 质疑对象是什么；是否影响当前任务或长期规则；合理与不合理两种判断；是否需要写入以及写入位置 | 已完成正反判断，且修改确实有长期消费价值；或 Maker 明确确认只修当前 Draft | 不把质疑自动等同于修改授权；不为了缓和对话直接改长期规则；不把单次偏好写成全局要求 |
| 纠偏沉淀门槛 | 把 Maker 的单次纠偏、临时偏好、一次审阅意见、当前任务限制或 AI 的一次错误，写成长期规则、默认禁止项、Skill reference 规则、模板规则、`AGENTS.md` 规则或 Architecture Decision | 不直接沉淀为长期规则；先按写回规则判断删除、移动、登记后续或提出长期规则候选 | 该纠偏是否具有跨任务、跨 Phase 或未来项目复用价值；现有边界是否已覆盖；应写入哪个权威位置；应抽象成什么原则 | Maker 明确确认其长期复用价值、适用范围和写入位置，且写入不会重复维护已有规则 | 如果只是当前 Draft 修正，直接修正文档但不新增长期规则；如果归属不清，登记为后续判断任务；如果现有边界已覆盖，只引用既有边界 |
| Architecture Decision 候选写回门槛 | 新规则可能长期约束多个任务、多个 Phase 或未来项目，且不能更合适地放在其他文档 | 提出候选写回，不直接修改 `SPECS/ARCHITECTURE_DECISIONS.md` | 是否确认该规则具有长期跨任务/跨 Phase 约束力；是否现有 Decision 已覆盖；是否批准写入 | Maker 明确批准候选内容和写入位置 | 不写入 Architecture Decisions；若只是单次纠偏，按写回规则删除、移动或登记后续 |

## 4. 默认不会做什么

触发硬性门槛后，AI 默认不会：

- 自动切换 Phase；
- 自动改变 AI 角色；
- 自动把 Maker 的“继续”解释为 Git 授权；
- 自动暂存、提交、推送、合并或清理分支；
- 自动改写权威文档职责；
- 自动把新想法纳入当前范围；
- 自动把临时纠偏写成长久规则；
- 自动把一次审阅意见抽象成 Skill 或模板默认规则；
- 自动交给 Builder 执行边界不完整的任务；
- 自动绕过状态入口冲突；
- 自动在污染上下文中继续关键写入；
- 自动把压缩摘要当作权威状态；
- 自动用通用 Skill 写法、外部工具习惯、模型默认语言或工具能力覆盖本地项目协议；
- 自动把一种产物承载类型的格式规则套到另一种产物上；
- 自动把当前项目 Phase 文档结构、文档状态表或状态入口规则套到 Skill runtime reference、不会实例化为目标项目 `DOCS/` 权威文档的 Skill asset / template、代码、配置或 Prompt 正文；
- 自动把文件名、代码、标准技术名词可保留英文解释为 Markdown 正文可以默认英文；
- 自动把 Maker 的质疑解释为必须修改，或为了迎合质疑直接改写长期规则；
- 自动修改 `SPECS/ARCHITECTURE_DECISIONS.md`。

## 5. Maker 确认字段

当 AI 需要 Maker 授权继续时，确认信息必须足够具体。

| 门槛类型 | 最小确认字段 |
| --- | --- |
| Phase | 目标 Phase 或阶段动作、Exit Criteria 处理方式、是否更新状态入口 |
| Git | 具体 Git 动作、目标分支、文件范围、远端对象、异常停止条件 |
| 权威文档 | 目标文档、状态变化、权威职责变化、受影响索引 |
| 范围 | 新范围内容、当前任务是否纳入、后续记录位置 |
| Builder | Ticket 路径、缺失字段补齐结果、验收和验证方式 |
| 未闭环任务 | 当前 Diff 是否属于续作、是否先闭环、允许继续的任务范围 |
| 上下文完整性 | 是否重开上下文、当前允许继续任务、必读恢复文件、当前 Diff 处理方式、禁止依赖聊天记忆的判断项 |
| 本地协议与输出约束 | 适用的本地协议路径、目标输出或文件、语言和格式规则、内容承载规则、读写范围、工具边界、允许例外的字段或范围 |
| 承载类型错位 | 产物承载类型、目标路径域、适用写法、禁止套用的规则、是否允许例外 |
| 质疑回应与非迎合 | 质疑对象、合理性判断、不合理性判断、建议动作、是否写入长期规则、写入位置 |
| 纠偏沉淀 | 纠偏内容、长期适用范围、现有边界覆盖判断、写入位置、抽象后的原则表述 |
| Architecture Decision | 候选规则、长期约束范围、现有 Decision 覆盖判断、写入位置 |

如果 Maker 的确认只表达方向、态度或结果接受，而不包含上表所需字段，AI 应继续停在门槛处。

## 6. 验证场景映射

### S2 Maker 说“继续”

**输入场景**

- 当前 Diff 等待审阅；
- Maker 只说“继续”。

**触发门槛**

- Git 门槛；
- 未闭环任务门槛；
- 必要时 Phase 门槛。

**通过标准**

- AI 不把“继续”解释为 Git 授权、Phase 切换或里程碑闭环；
- AI 先判断继续的是当前任务修改、同一里程碑后续 Ticket、手动 Git 闭环还是阶段门。

### S3 Git 未闭环

**输入场景**

- 工作区存在未提交 Diff、未推送提交或未合并任务分支；
- Maker 发起无关新写入任务。

**触发门槛**

- 未闭环任务门槛；
- Git 门槛。

**通过标准**

- AI 停止无关新写入任务；
- 报告当前分支、Diff、未推送提交或远端状态；
- 不创建新无关分支，不混入新任务。

### S4 想切换 Phase

**输入场景**

- Maker 表达想进入下一 Phase；
- 当前 Exit Criteria 尚未逐项检查或状态入口尚未更新。

**触发门槛**

- Phase 门槛；
- 权威文档门槛。

**通过标准**

- AI 输出阶段门检查、缺口、风险和选项；
- 未经 Maker 明确阶段决定，不更新 Phase；
- 不把阶段愿望当成阶段切换授权。

### S6 Ticket 不完整

**输入场景**

- Ticket 缺少验收标准、验证步骤、允许/禁止范围或完成后更新项；
- Maker 想让 Builder 执行。

**触发门槛**

- Builder 交接门槛。

**通过标准**

- AI 拒绝交给 Builder；
- 明确缺失字段；
- 回到 Planning 或当前 Ticket 补齐边界。

### S8 权威文档冲突

**输入场景**

- `PROJECT_STATE.md` 指向不存在或冲突文件；
- 或多个 Active 文档维护同一事实。

**触发门槛**

- 权威文档门槛；
- 未闭环任务门槛；
- 必要时 Architecture Decision 候选写回门槛。

**通过标准**

- AI 停止阶段推进；
- 报告冲突来源、差异和影响；
- 不自行选择方便版本；
- 修复前不进入无关新写入任务。

### 纠偏沉淀场景

**输入场景**

- Maker 指出某段内容不合理；
- AI 想把这次纠偏写成 Skill reference、模板规则、`AGENTS.md` 规则或 Architecture Decision；
- 该纠偏可能只是当前 Draft 的局部修正。

**触发门槛**

- 纠偏沉淀门槛；
- 必要时权威文档门槛；
- 必要时 Architecture Decision 候选写回门槛。

**通过标准**

- AI 先判断这是当前 Draft 修正、删除/移动/后续登记，还是长期规则候选；
- 没有 Maker 明确确认时，不把单次纠偏写成默认长期规则；
- 若现有边界已覆盖，只引用既有边界，不重复新增规则；
- 若确需沉淀，先说明适用范围、写入位置和抽象后的原则，等待 Maker 确认。

### 上下文完整性场景

**输入场景**

- 会话上下文过长或自动压缩后，AI 引用过期分支、过期任务、错误授权或错误门槛状态；
- Maker 多次指出 AI 的认知、门槛限制或动作判断已经偏差；
- AI 准备继续写入关键文档、执行 Git、切换 Phase 或沉淀长期规则。

**触发门槛**

- 上下文完整性门槛；
- 必要时未闭环任务门槛；
- 必要时 Git、Phase、权威文档或纠偏沉淀门槛。

**通过标准**

- AI 停止关键动作，不继续在污染上下文中推进；
- AI 建议 Maker 重开上下文，或只输出最小恢复胶囊；
- 恢复胶囊要求新会话重新读取权威文件；
- 自动压缩摘要不能替代 `AGENTS.md`、`PROJECT_STATE.md`、当前 Ticket 和相关 Skill reference；
- 若 Maker 要求在当前会话继续，AI 只可做低风险修正，并先从权威文件重新确认当前状态。

### 本地协议输出约束偏离场景

**输入场景**

- 已接入项目中 AI 已读取目标项目路径 `AGENTS.md`；未接入项目中 AI 已读取 Skill 资产路径 `references/project-intake-and-initialization.md`；
- 本地协议要求默认使用中文交流和编写 Markdown 正文，并规定写入、Git、文档承载或工具使用边界；
- AI 因 Skill 通用写法、外部工具习惯、模型惯性或工具可用性，准备输出不符合本地协议的回复、Skill 入口正文、reference、项目文档或执行动作。

**触发门槛**

- 本地协议与输出约束门槛；
- 必要时权威文档门槛；
- 必要时纠偏沉淀门槛。

**通过标准**

- AI 在写入前停止并确认本地语言规则；
- Markdown 正文使用本地协议要求的语言；
- 输出承载位置、读写范围和工具使用方式符合本地协议；
- 只在文件名、代码、标准技术名词或 Maker 明确授权的例外范围内保留英文或偏离默认规则；
- 如果本地协议与 Skill 通用规范冲突，报告冲突并以本地协议优先，除非 Maker 明确批准具体例外。

### 承载类型错位场景

**输入场景**

- 当前项目正在孵化 Skill、App、内容作品、模板、脚本、配置或其他非项目 Phase 文档产物；
- AI 准备生成或修改产物；
- AI 准备用当前 Project Incubator 项目文档结构、文档状态表、状态入口规则、Prompt 规则或其他承载物规则套用到该产物。

**触发门槛**

- 承载类型错位门槛；
- 必要时本地协议与输出约束门槛；
- 必要时权威文档门槛或纠偏沉淀门槛。

**通过标准**

- AI 在写入前说明产物承载类型；
- AI 明确路径域是目标项目路径、Skill 资产路径还是当前 Project Incubator 仓库路径；
- AI 明确适用写法和禁止套用的规则；
- 输出结构符合该承载物用途；
- Maker 如需例外，已明确确认例外对象和范围。

### 质疑回应与非迎合场景

**输入场景**

- Maker 对 AI 的解释、方案、规则写入或 Skill 设计提出质疑；
- 质疑可能是正确的，也可能只是需要讨论；
- AI 准备立即顺着质疑改写协作方式、门槛或长期规则。

**触发门槛**

- 质疑回应与非迎合门槛；
- 必要时纠偏沉淀门槛；
- 必要时权威文档门槛。

**通过标准**

- AI 先说明该质疑如果合理，应如何修改更好；
- AI 同时说明该质疑如果不合理，为什么不应修改；
- AI 基于权威文档和当前任务边界给出建议；
- 只有在判断确有长期消费价值，或 Maker 明确要求修当前 Draft 时，才执行写入；
- 不把讨论过程、迎合性表态或单次偏好写成长期规则。
