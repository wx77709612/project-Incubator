# AI Agent 协作项目设计经验沉淀


## 1. AI Agent 协作设计流程规范

（给 Agent 使用）

定义：

未来当 Agent 参与一个新的复杂项目设计时，必须遵循什么流程。

例如：

1. 先确认项目目标
2. 确认最终实现目标和服务对象
3. 确认设计文档最终服务对象
4. 建立设计文档体系
5. 明确每个文档职责
6. 再开始生成具体设计文档
7. 设计过程中持续检查职责边界


这一章是规则。


---

## 2. 设计过程中的问题沉淀

（主要给人类阅读）

记录：

我们过去遇到的问题：

- 为什么发生；
- 错误模式是什么；
- 最终形成什么原则。


例如：

### 问题 1：没有先确认设计文档服务目标

问题：

一开始直接进入 Design 文档生成。

导致：

- 不明确 Design 是架构文档还是实现文档；
- 后续不断追加 API、字段、流程；
- 文档职责膨胀。


最终原则：

设计前必须明确：

- 项目目标；
- 文档目标；
- 实现目标。


---

### 问题 2：没有先设计文档体系

问题：

直接创建：

- Workflow Design；
- Gate Design；
- Context Model。


导致：

不知道：

- 字段应该放哪里；
- Contract 是否需要独立；
- Runtime 是否应该包含模型定义。


最终原则：

复杂项目必须先建立：

Document Architecture。


---

### 问题 3：Architecture、Design、Contract、Runtime 混淆

问题：

同一个概念被多个文档定义。


例如：

Context：

既包含：

- 数据模型；
- API；
- 权限；
- Runtime 调用。


最终原则：

必须区分：

Architecture：

定义系统边界。


Design：

定义领域模型。


Contract：

定义交互协议。


Runtime：

定义执行过程。


---

### 问题 4：发现缺失内容时错误地追加，而不是判断职责

问题：

发现缺少内容：

直接修改当前文档。


导致：

文档越来越长。


最终原则：

发现缺失内容时：

先判断：

“这个内容属于哪个层级？”

而不是：

“在哪里增加章节？”

---

### 问题 5：Review 方式错误

问题：

只检查单个文档完整性。


忽略：

- 文档定位；
- 上下游关系；
- Source of Truth。


最终原则：

Review 顺序：

1. 判断文档定位；
2. 判断职责完整性；
3. 判断跨文档一致性；
4. 判断是否可实现。


---

### 问题 6：冻结标准不明确

问题：

认为：

一个文档冻结 = 整个系统完成。


最终原则：

冻结代表：

该文档成为稳定契约。

不代表：

所有后续设计完成。
